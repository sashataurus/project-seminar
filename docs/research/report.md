# ЛР 2 — обоснование актуальности ВКР

**Тема ВКР:** Разработка веб-приложения для автоматизированной обработки, анализа и визуализации структурированных табличных данных

**Вклад каждого участника при командной работе:** 
- **Кириченко Александра Петровна:** общая концепция и формулировка предметной области; проектирование схемы связывания разнородных табличных данных и конвейера обработки (ETL); разработка методики генерации синтетического датасета образовательной воронки; проведение анализа литературы по структурированию данных и образовательному дата-майнингу.

### Выводы по обзору

1. **Что уже сделано:** В академической литературе глубоко исследованы математические принципы нормализации таблиц (Wickham), декларативные грамматики визуализации (Vega-Lite) и базовые метрики Educational Data Mining (Romero, Baker). Существуют зрелые алгоритмы проверки контрактов данных (Data Contracts/Validation) при пакетной обработке. В последние два года активно развиваются подходы Text-to-Insight на базе LLM.
2. **Нерешенные вопросы и пробелы:** Большинство решений либо требуют высокой технической квалификации (написание Python/SQL-скриптов для ETL), либо представляют собой громоздкие корпоративные BI-системы, требующие развертывания постоянной СУБД со статичной схемой. На стыке обработки разнородных Excel-шаблонов отсутствует законченное легковесное веб-решение, способное «из коробки» валидировать шаблоны, автоматически связывать сквозную воронку (отбор $\rightarrow$ зачисление $\rightarrow$ ведомость $\rightarrow$ обратная связь $\rightarrow$ трудоустройство) и привлекать языковые модели для генерации содержательных управленческих рекомендаций без риска утечки конфиденциальных персональных данных.

## 3. Обзор и сравнение аналогов

### Прямые аналоги

1. **Apache Superset** ([https://superset.apache.org/](https://superset.apache.org/))  
   Зрелая open-source BI-платформа корпоративного уровня для визуализации и исследования данных.  
   *Ограничения:* Не предназначена для прямого парсинга и сопоставления произвольных «сырых» Excel-файлов; требует предварительной настройки реляционной базы данных и строгого SQL-моделирования; отсутствует специализированная образовательная логика связывания сущностей; нет встроенного агента автоматической интерпретации инсайтов.

2. **Yandex DataLens** ([https://cloud.yandex.ru/services/datalens](https://cloud.yandex.ru/services/datalens))  
   Облачный сервис бизнес-аналитики и визуализации данных от Яндекса.  
   *Ограничения:* Зависимость от проприетарной облачной инфраструктуры (vendor lock-in); сложности с соблюдением требований локальной безопасности при работе с внутренними таблицами; ограниченные возможности гибкой предобработки ненормализованных таблиц Excel без промежуточного ETL; отсутствие модуля генерации аналитических выводов на базе ИИ.

3. **Metabase** ([https://www.metabase.com/](https://www.metabase.com/))  
   Популярный open-source инструмент для бизнес-аналитики с простым интерфейсом конструирования дашбордов.  
   *Ограничения:* Ориентирован на прямое подключение к SQL-базам; слабая поддержка загрузки и автоматического слияния нескольких разнородных XLSX-файлов; отсутствует встроенная подсистема валидации схем документов при загрузке пользователем-методистом.

### Косвенные аналоги

1. **Microsoft Excel / Power Query & Power BI** ([https://powerbi.microsoft.com/](https://powerbi.microsoft.com/))  
   Классический офисный стек с мощным функционалом построения аналитических моделей (DAX, Power Query) и сводных отчетов.  
   *Ограничения:* Проприетарная экосистема с высокими лицензионными ограничениями в РФ; высокий порог входа для методистов и кураторов (необходимость писать скрипты Power Query/VBA); отсутствие централизованного веб-доступа и изолированного контура локального ИИ-анализа.

2. **Google Forms + Google Sheets + Looker Studio** ([https://lookerstudio.google.com/](https://lookerstudio.google.com/))  
   Связка облачных офисных инструментов для сбора и последующей визуализации данных опросов и ведомостей.  
   *Ограничения:* Хранение данных на зарубежных серверах (критично для образовательных программ РФ); ручное сведение таблиц через формулы `VLOOKUP`/`XLOOKUP`; нестабильность при изменении структуры колонок; отсутствие комплексной валидации форматов данных.

3. **Кастомные скрипты на Python (Pandas + Streamlit / Dash)** ([https://streamlit.io/](https://streamlit.io/))  
   Индивидуальные скриптовые веб-приложения для автоматизации рутинной обработки таблиц конкретного формата.  
   *Ограничения:* Отсутствие универсальности (любое изменение шаблона ломает пайплайн); необходимость сопровождения кода разработчиком; отсутствие разграничения ролей и механизмов безопасного изолированного выполнения.

### Таблица сравнения

**Почему выбраны эти критерии:**  
- *Автоматическая валидация Excel-шаблонов:* критически важна, так как операторы и методисты регулярно допускают ошибки в форматах ячеек, именах колонок и пропусках.
- *Сквозное связывание сущностей воронки без СУБД:* позволяет объединить этапы «отбор — зачисление — успеваемость — CSAT/NPS — офферы» по ФИО/идентификаторам без необходимости администрирования SQL-сервера.
- *Встроенный модуль интеллектуальной аналитики (LLM-агент):* требование для автоматического формирования выводов (например, обнаружение аномального падения NPS на курсе по Python и генерация совета методистам).
- *Self-hosted развертывание:* обеспечивает защиту персональных данных обучающихся и независимость от внешних облачных провайдеров.
- *Низкий порог входа:* интерфейс должен быть интуитивен для куратора образовательной программы, не умеющего писать SQL-запросы или формулы DAX.
- *Интерактивные веб-дашборды «из коробки»:* генерация графиков и срезов без ручной настройки осей для каждого нового набора данных.

| Критерий | Apache Superset | Yandex DataLens | MS Excel / Power BI | Streamlit (скрипт) | Наше решение (план) |
|---|---|---|---|---|---|
| Автоматическая валидация Excel-шаблонов при загрузке | Нет | Нет | Частично (Power Query) | Требует ручного кода | Да (декларативные схемы) |
| Сквозное автоматическое связывание воронки курсов | Только через SQL JOIN | Только через датасеты SQL | Ручные связи в модели | Ручные merge в Pandas | Да (предустановленные ключи связывания) |
| Встроенный ИИ-аналитик метрик и генератор рекомендаций | Нет | Нет | Copilot (платный/зарубежный) | Нет | Да (локальный/API LLM-агент) |
| Возможность полного Self-hosted развертывания | Да | Только Cloud | Частично (серверные лицензии) | Да | Да (Docker-контейнеризация) |
| Порог входа для методистов и операторов | Высокий (нужен SQL) | Средний | Средний (формулы/DAX) | Высокий (нужен Python) | Низкий (drag-and-drop файлов) |
| Специализированный расчет метрик (CSAT, NPS, Cor) | Через пользовательские SQL-формулы | Через калькулируемые поля | Через формулы DAX | Через ручные скрипты | Встроенные образовательные формулы |
| Отсутствие привязки к внешним платным сервисам | Да (open-source) | Нет (тарифы облака) | Нет (проприетарное ПО) | Да (open-source) | Полностью открытый стек |

### Выводы по сравнению

Существующие индустриальные BI-платформы (Apache Superset, DataLens) решают задачу универсальной визуализации, но перекладывают этап предварительной очистки, нормализации и связывания таблиц на внешние ETL-инструменты или квалифицированных инженеров данных. Офисные пакеты (Excel, Power BI) требуют регулярной ручной настройки и не обеспечивают надежного централизованного веб-процесса с контролем версий и схем.

Разрабатываемое веб-приложение устранит эти ограничения за счет:
1. Реализации специализированного шлюза валидации и трансформации, ориентированного на регламентированные Excel-шаблоны образовательных программ.
2. Внедрения интеллектуального интерпретатора данных, который автоматизирует рутинную аналитическую работу (расчет NPS/CSAT, сопоставление результатов выпускных экзаменов со статусами трудоустройства) и формирует текстовые заключения для академических руководителей.
3. Полной автономности развертывания (on-premise / self-hosted), исключающей риски компрометации персональных данных учащихся.

### Актуальность исследования

Современные образовательные инициативы, корпоративные академии и проектные школы оперируют большими объемами гетерогенных табличных данных, фиксирующих этапы жизненного цикла студента: конкурсный отбор, академическую успеваемость, обратную связь и карьерные исходы. В большинстве случаев сбор этих сведений осуществляется децентрализованно с использованием разнородных Excel-таблиц. По данным академических обзоров (Kandel et al., Abadi et al.), специалисты тратят до $70\text{--}80\%$ рабочего времени на рутинные операции по очистке, ручному сведению и проверке целостности таблиц. 

Использование тяжеловесных BI-инструментов зачастую экономически и технически нецелесообразно из-за дефицита SQL-компетенций у методистов и повышенных требований законодательства РФ к защите персональных данных обучающихся (ФЗ-152). Создание специализированного веб-приложения с автоматизированным ETL-конвейером и встроенным ИИ-модулем содержательной интерпретации метрик позволит сократить время подготовки аналитических срезов с нескольких рабочих дней до минут, снизить влияние человеческого фактора и оперативно корректировать учебные программы на основе объективных статистических индикаторов.

### Цель исследования

Разработка, реализация и экспериментальное исследование веб-приложения для сквозной автоматизированной валидации, нормализации, аналитической обработки и интерактивной визуализации структурированных табличных данных образовательных программ с применением методов интеллектуальной интерпретации метрик.

### Задачи исследования

1. **Анализ предметной области и формализация контрактов данных:** исследовать структуры типовых отчетных таблиц образовательных воронок («Отборы», «Зачисленные», «Ведомость», «Обратная связь», «Трудоустройство») и разработать декларативные JSON-схемы для их валидации.
2. **Проектирование архитектуры веб-приложения:** разработать компонентную схему системы (клиентская часть, серверный REST API, модуль фоновой обработки ETL, модуль взаимодействия с языковой моделью).
3. **Разработка алгоритма и модуля автоматизированного преобразования (ETL):** создать программный модуль для парсинга Excel-файлов, верификации корректности типов данных, автоматического устранения аномалий и объединения записей в единую аналитическую витрину.
4. **Разработка аналитического и ИИ-модуля:** реализовать вычислительный конвейер расчета базовых метрик (конверсии этапов, средние баллы, CSAT, NPS) и алгоритм генерации текстовых аналитических заключений с помощью интеграции языковой модели (LLM).
5. **Разработка клиентской части и интерактивных дашбордов:** создать адаптивный веб-интерфейс (Frontend) с графическими компонентами когортного анализа, матриц корреляций и детализированных табличных представлений.
6. **Генерация репрезентативного синтетического набора данных и тестирование:** разработать генератор псевдоанонимизированных синтетических данных с заданными статистическими распределениями для всесторонней апробации функциональности и оценки производительности системы.

### Датасеты и сервисы

В связи с требованиями конфиденциальности и защитой персональных данных реальных корпоративных и академических программ в исследовании используется программно сгенерированный комплексный синтетический датасет. 

**Состав синтетического набора данных:**
1. `selections.xlsx` («Отборы»): 1000–3000 записей (ФИО, вуз, город, направление подготовки, баллы по вступительным испытаниям, временные затраты).
2. `admitted.xlsx` («Список зачисленных»): 300–500 записей (ФИО, вуз, выбранный трек обучения, источник привлечения).
3. `grades.xlsx` («Ведомость успеваемости»): 300–500 записей (ФИО, направление, баллы за практические домашние задания, баллы за итоговый проект, итоговый балл, статус завершения курса).
4. `feedback.xlsx` («Обратная связь»): 250–400 записей (ФИО, направление, числовые оценки удовлетворенности модулями, значения CSAT, значения NPS, текстовые отзывы).
5. `employment.xlsx` («Трудоустройство»): 150–300 записей (ФИО, направление, качественный отзыв ментора, текущий статус: «проходит собеседования», «отказ (hard skills)», «отказ (soft skills)», «получен оффер на стажера», «получен оффер на джуна»).
